# 현재 운동 코스 검토

검토일: 2026-10-28. 대상은 현재 작업 트리의 `coach-engine.js`와 `app.js`가 실제 생성하는 코스다. 안내 문서의 의도와 구현 결과를 구분했다. 코드 정적 검토와 가상 프로필 시뮬레이션을 수행했으며, 실제 이용자의 체력 변화나 운동 자세를 측정한 임상·현장 평가는 아니다. 이번 검토로 추천 코드를 수정하지 않았다.

## 종합 판단

**운동 습관 형성과 입문자의 기초 근력·근지구력 운동을 돕는 틀로는 유용하다. 그러나 현재 상태를 모든 주요 근육군에 균형 잡힌 자극을 주고, 개인별 적정 강도와 회복까지 관리하는 충분히 검증된 운동 처방 시스템으로 평가하기는 어렵다.**

주 2~3회 전신운동, 다관절 맨몸운동, 수행 피드백이라는 방향은 합리적이다. 다만 효과를 좌우하는 실제 노력 수준·부하·완료 반복 수를 충분히 확인하지 못하고, 동작 분류와 추천 후 검증에 구체적인 결함이 있다.

## 비교한 근거

- [ACSM 2026 공식 안내](https://acsm.org/resistance-training-guidelines-update-2026/): 일관된 수행과 목표에 맞는 훈련 변수를 강조한다. 복잡한 구성 자체가 효과의 조건은 아니다.
- [ACSM 2026 Position Stand 원문](https://pmc.ncbi.nlm.nih.gov/articles/PMC12965823/): 건강한 성인에게 주요 근육군을 포함한 충분한 노력의 저항운동을 주 2회 이상 권고한다. 장기적인 발전에는 자극 증가가 중요하며, 실패까지 매번 수행해야 하는 것은 아니다. 근비대를 최적화하려는 높은 주당 운동량 권고를 초보자의 최소 건강 기준으로 혼동해서는 안 된다.
- [WHO 성인 신체활동 권고](https://www.who.int/europe/news-room/fact-sheets/item/physical-activity): 유산소 활동과 주요 근육군의 근력운동을 함께 다룬다. 근력 루틴만으로 전체 신체활동 권고가 충족됐다고 볼 수 없다.

이 근거는 일반적인 운동 원칙을 지지한다. 이 앱의 선택 규칙이나 안전 대체 규칙 자체가 연구에서 검증됐다는 뜻은 아니다.

## 실제 코스 예시

다음 입력으로 엔진을 직접 실행했다.

```text
운동 경험: 보통
정자세 푸시업 최대: 12회
목표 시간: 30분
주당 횟수: 3회
목표: 균형
불편 부위: 없음
진행도 추가치: 없음
```

| 루틴 | 본운동 구성 | 기본 반복/시간 |
|---|---|---|
| A | 일반 푸시업 / 스쿼트 / T 레이즈 / 옆으로 누워 다리 들기 / 버드독 | 8회 / 14회 / 12회 / 좌우 12회씩 / 좌우 8회씩 |
| B | 천천히 스쿼트 / 무릎 푸시업 / T 레이즈 / 옆으로 누워 다리 들기 / 플랭크 | 12회 / 9회 / 12회 / 좌우 12회씩 / 30초 |
| C | 일반 푸시업 / 한발 브리지 / 스쿼트 / 리버스 스노우 엔젤 / 버드독 | 8회 / 좌우 8회씩 / 14회 / 10회 / 좌우 8회씩 |

각 본운동을 3라운드 수행하고, 4개 준비운동과 2개 마무리 동작을 추가한다. 준비·마무리는 현재 각 60초라서 합계 6분이다. 종목 사이 기본 휴식은 균형 목표 25초이며, 본운동 라운드 경계에는 기본 55초를 사용한다.

주 3회 이 코스를 수행한다면 일반적으로 푸시·스쿼트 범주에 각 9세트가 생긴다. 그러나 이를 모든 근육군의 유효 세트 9개로 간주할 수는 없다. 동작별 자극 부위와 실제 노력 수준이 다르고, 등 당기기 동작은 없다.

## 장점

1. 푸시업·스쿼트·브리지 등 접근하기 쉬운 동작으로 시작한다.
2. 세션마다 다른 범주의 동작을 순환해 한 부위의 연속 수행을 줄인다.
3. 주 2회 A/B, 주 3회 이상 A/B/C 순환으로 다음 운동을 쉽게 결정한다.
4. 단계별 설명과 시연, 일시정지, 수동 횟수 조절로 사용자의 수행을 돕는다.
5. 수행 피드백을 다음 세션에 반영하려는 점진적 조정 구조가 있다.
6. 기록·백업과 월별 달력은 지속적인 참여를 확인하는 데 도움이 된다.

## 주요 문제와 근거

### 1. 등 당기기 운동이 없다 — 구성의 한계

`sequences.pull`은 W 레이즈 → T 레이즈 → 리버스 스노우 엔젤이다. 어깨 주변과 상부 등의 보조운동으로는 활용할 수 있으나, 로우·풀다운·풀업과 동일한 당기기 부하를 제공하는 구성은 아니다.

따라서 푸시업이 있다는 이유로 상체 밀기·당기기가 균형 잡혔다고 평가할 수 없다. 장비 없는 조건을 유지한다면 이 한계를 명시하고, 장비 옵션을 허용한다면 밴드 로우 등 실제 당기기 종목을 별도 도입하는 방향이 적합하다. 임의의 문틀·가구에 체중을 거는 동작을 기본 대안으로 제시해서는 안 된다.

코드: `coach-engine.js`의 `MOVES`, `sequences`.

### 2. 고관절 폄과 다리 벌리기를 하나의 난이도 사다리로 취급한다 — 분류 문제

`sequences.hinge`는 브리지 → 옆으로 누워 다리 들기 → 한발 브리지다. 브리지는 고관절 폄, 옆으로 누워 다리 들기는 주로 고관절 벌림으로 움직임이 다르다. 같은 동작의 저부하·고부하 변형처럼 교체하면 운동 목적도 함께 바뀐다.

위의 보통 프로필에서는 A와 B의 해당 자리가 모두 다리 벌리기가 되어, 고관절 폄 동작은 C에만 나온다. 고관절 폄과 벌림을 별도 패턴으로 분리하고, 주요 패턴을 주간 단위로 확인하는 방식이 필요하다.

### 3. ‘너무 어려웠어요’가 기본 부하를 실제로 낮추지 못한다 — 우선 수정할 로직

`applyFeedback()`은 어려움 평가를 받으면 추가 반복치 `bonus`를 2 줄이지만 하한은 0이다. 이미 0인 신규 이용자에게는 기본 횟수도 난도 단계도 내려가지 않는다. 올라간 `tier`를 내리는 경로도 없다.

초기 상태에서 푸시업 3세트를 모두 어렵다고 평가하는 상황을 실행한 결과:

```json
{"push":{"tier":0,"bonus":0,"easySessions":0}}
```

즉 자동 조절은 추가 부담을 걷어내는 수준이며, 기본 처방이 어려운 이용자를 충분히 낮춰 주는 구조가 아니다. 앱의 수동 횟수 조절은 가능하지만 자동 추천의 결함을 대신 검증해 주지는 않는다.

개선: 기본 반복 범위의 하향, 동작 난도 후퇴, 세트 수 감소 중 적절한 경로를 마련하고 변경 후 사용자의 다음 수행 결과를 확인한다.

### 4. 실제 노력 수준과 과부하가 충분히 측정되지 않는다

대부분 종목은 고정 기본 반복 수에 추가치를 더한다. 실제 완료 반복 수, 가동범위, 세트 종료 시 남은 반복 여력, 통증과 단순 피로의 구분을 기록하지 않는다. 일반 푸시업도 목표 계산에 8회 상한이 있어 같은 횟수가 사람마다 전혀 다른 난도가 될 수 있다.

따라서 화면에 ‘마지막 2~3회가 어렵게’라고 적는 것만으로 적절한 노력 수준을 달성했다고 볼 수 없다. 남은 반복 여력의 간단한 안내, 실제 수행량 입력, 동작별 반복 범위와 달성 조건이 필요하다. 매번 실패까지 수행하도록 강제하는 방식은 권장 개선안이 아니다.

### 5. 불편 부위 대체 후 중복이 생긴다 — 재현된 구현 결함

경험 3종 × 목표 시간 3종 × 불편 부위 512조합 × A/B/C의 **13,824개 가상 입력**을 검사했다. 이때 푸시업 최대 횟수는 12회, 목표는 균형, 초기 진행도를 고정했다.

그중 **1,472개 입력에서 본운동 목록의 동작 ID 중복**이 발생했다. 이는 실제 이용자의 문제 발생률이 아니라 특정 입력 집합에 대한 소프트웨어 검사 결과다.

재현 예: 입문 / 30분 / 푸시업 최대 12회 / 무릎 불편 / A.

```text
푸시업 → 브리지 → W 레이즈 → 데드버그 → 브리지
```

대체 후보가 처음에는 달라도 `safeChoice()`를 거친 뒤 이미 선택한 동작으로 다시 변하는데, 최종 결과를 재검사하지 않기 때문이다. 원래 필요한 움직임의 자리가 사라지고 특정 동작이 두 배 배정될 수 있다.

개선: 대체를 적용한 최종 목록에 중복·패턴·세트 수 검사를 수행한다.

### 6. 29개 등록 동작과 실제 자동 코스는 다르다

운동 경험·푸시업 능력·난도 단계·루틴을 바꿔 자동 선택 가능성을 확인했다. 현재 프로필 화면을 통한 일반적인 설정에서는 아래 6개가 자동 선택되지 않았다.

- 높은 지지대 푸시업: 선택 사다리에 없음.
- 의자 스쿼트: 안정적인 의자 여부를 프로필에서 입력하지 않아 기본 스쿼트로 대체됨.
- 리버스 런지·클램셸·좌우 사이드 플랭크: 선택 사다리에 없음.

의자 스쿼트는 코드에 `stableChair:true`를 직접 전달하면 선택되지만, 현재 프로필 UI에는 해당 입력이 없다. 특정 미디어·안내가 존재한다는 사실을 자동 코스의 다양성으로 계산해서는 안 된다.

또한 20분 코스는 마지막 코어 자리를 일괄 삭제한다. 스쿼트·푸시업에도 몸통 안정화 요구는 있으므로 ‘코어를 전혀 사용하지 않는다’는 뜻은 아니지만, 짧은 코스의 주간 구성도 별도로 검토해야 한다.

### 7. 감량·심폐체력 목표를 충분히 구현하지 않는다

감량 목표는 주로 휴식을 짧게 하고 안내 문구를 바꾼다. 근력 목표는 A의 푸시 난도 등을 바꾸지만, 전체 훈련을 목표별로 크게 구분하지 않는다. 유산소 활동량을 계획·기록하거나 주간 목표와 합산하는 기능은 없다.

WHO는 일반 성인에게 주 150~300분 중강도 또는 75~150분 고강도 유산소 활동과 주 2일 이상의 주요 근육군 강화 활동을 권고한다. 앱의 ‘30분 운동’은 준비·마무리·휴식이 섞여 있으므로 그 시간을 그대로 유산소 활동 30분으로 계산하면 안 된다.

개선: 근력 루틴과 걷기 등 유산소 활동 목표를 구분하고, 체중 변화만으로 훈련의 질이나 감량 효과를 판정하지 않는다.

### 8. 회복·시간·시연 일치 검증이 부족하다

- 주당 횟수는 다음 A/B/C 선택에 반영되지만, 최근 운동의 부하·연속 운동일·피로를 바탕으로 회복일을 배정하지 않는다. 주 5회라는 숫자만으로 위험하다고 단정할 수는 없지만, 같은 전신 코스를 얼마나 강하게 반복하는지 구분이 필요하다.
- 목표 20/30/45분은 실제 동작 수행시간을 합산해 최적화한 예산이 아니다. 새 45분 프로필의 기본값은 3라운드인데 `recommendedRounds()`는 4를 반환해 프로필 변경·초기화 경로에 따라 결과가 다를 수 있다.
- 자료 연결 검사는 자세의 정확도, 팔꿈치/손바닥 지지, 좌우 방향, 무릎 지지 여부를 전문 검수한 것과 다르다. 기존 Pexels 후보의 수동 확인 메모가 여전히 남아 있다.
- 불편 부위만으로 고정 대체하는 규칙은 통증 원인을 판별하지 않는다. 증상이 있는 모든 사람에게 대체 동작이 적합하다고 보장할 수 없다.

## 과도하게 문제 삼지 않아야 할 부분

- 맨몸운동이라는 이유만으로 효과가 없다고 볼 수 없다. 적절한 노력과 지속성이 중요하다.
- 모든 근육군을 한 세션에 반드시 포함해야 한다고 단정하지 않는다. 주간 구성도 함께 볼 수 있다.
- 종목 사이 20~25초 휴식은 같은 종목의 세트 사이 휴식과 다르다. 이 앱은 서로 다른 운동을 순환하므로 같은 부위가 다시 돌아오기까지 더 긴 시간이 흐른다. 고정 휴식 숫자만으로 실패한 프로그램이라고 평가하지 않았다.
- 느린 템포는 동작 제어에 활용할 수 있으나 일반 속도보다 항상 효과가 우월하다는 근거로 사용하지 않는다.
- 복잡한 주기화·수많은 종목이나 특정 세트 수가 모든 초보자의 필수 조건은 아니다.

## 개선 우선순위

| 순서 | 개선 | 이유 |
|---|---|---|
| 1 | 어려움 평가 시 실제 하향 조정, 대체 후 최종 중복 검사 | 현재 코드로 재현되는 추천 결함 |
| 2 | 고관절 폄/벌림 분리, 밀기/당기기 한계 명시, 주간 패턴 검증 | 전신 구성의 균형 |
| 3 | 실제 수행량·남은 반복 여력·회복 상태 반영 | 개인별 적정 자극과 장기 발전 |
| 4 | 장비 여부 입력, 자동 선택에서 빠진 종목의 역할 정리 | 가용 동작과 추천 동작의 일치 |
| 5 | 유산소 활동 보완, 목표 시간·라운드 기준 통일 | 목표와 서비스의 일치 |
| 6 | 시연 자료의 동작별 확인, 실제 사용자 사용성·경과 검토 | 코드 검사와 실제 효과의 간극 축소 |

**최종 평가:** 기본 방향은 살릴 가치가 있지만, 현재의 자동 추천을 완성된 과학적 운동 처방으로 소개하는 것은 과하다. 먼저 구현 결함과 운동 패턴을 고친 뒤 입문자용 전신 근력 보조 프로그램으로 범위를 명확히 하고, 실제 이용 결과를 통해 보완하는 것이 적절하다.
