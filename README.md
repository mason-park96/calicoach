# 칼리코치 · Calisthenics Coach

개인 프로필에 맞춘 맨몸운동 루틴을 안내하고, 운동 이력과 체중 변화를 기기 안에 기록하는 한국어 PWA입니다.

이 문서는 **현재 작업 트리의 구현 상태**를 기준으로 작성했습니다. 저장소의 기존 버전 표기는 `v1.4.1`이며, 미디어 교체·월별 기록·체중 기록·초기화 기능 보완은 그 이후의 후속 수정입니다. 별도의 새 릴리스 번호나 온라인 배포 완료를 뜻하지 않습니다.

## 1. 설계 의도

칼리코치는 매번 운동 종목과 횟수를 직접 결정해야 하는 부담을 줄이고, **프로필 확인 → 오늘의 루틴 → 동작 학습 → 운동 수행 → 기록 확인**을 한 흐름으로 연결하는 것을 목표로 합니다.

- **집에서 이어가는 운동**: 매트 중심의 맨몸운동을 기본으로 합니다. 일부 변형 동작에는 안정적인 의자나 지지대가 필요합니다.
- **간편함을 최우선**: 설정에서 초급·중급·고급을 선택하고 평소에는 운동 완료만 누릅니다. 복잡한 평가나 추가 입력을 필수로 요구하지 않습니다.
- **짧은 화면 문구**: 중복 안내는 없애고 핵심만 표시합니다. 상세 기준은 펼쳐보기로 제공하며, 통증·삭제 경고와 동작 설명은 유지합니다.
- **설명 가능한 맞춤 추천**: 직접 선택한 운동 수준, 목표 시간, 주당 횟수, 불편 부위와 선택적인 수행 피드백을 명시적인 규칙으로 반영합니다.
- **기기 중심의 개인정보 관리**: 로그인이나 별도 백엔드 없이 한 브라우저 저장 공간에 하나의 프로필을 보관합니다.
- **동작을 보고 배우는 흐름**: 시연 자료와 함께 시작 자세·수행 방법·자세 확인 설명을 제공합니다.
- **지속성을 확인하는 기록**: 월별 운동 달력과 날짜별 체중 변화율로 자신의 진행 상황을 확인할 수 있습니다.

이 프로젝트는 성인의 개인 운동 보조 용도로 설계되었습니다. 운동 추천은 경험적 규칙이며 진단·치료·재활 처방이나 자동 자세 판정 기능은 아닙니다. W/T 레이즈 등 어깨 주변 보조운동만으로 기구를 사용하는 등 당기기 훈련을 충분히 대체할 수는 없습니다.

## 2. 제공 기능과 사용 흐름

하단 메뉴는 **홈 / 운동 기록 / 체중 / 설정**으로 구성됩니다.

| 화면 | 제공 서비스 |
|---|---|
| 프로필 | 이름·신체정보·현재/목표 체중·운동 경험·주당 횟수·목표 시간·운동 목표·불편 부위를 입력하고, `확인`을 눌러 저장합니다. |
| 홈 | 오늘의 추천 A/B/C 루틴, 종목별 시연 미리보기, 이번 주 완료 현황, 현재 체중과 목표 진행률을 표시합니다. |
| 운동 진행 | 준비·연습 → 운동별 세트의 상·하체 교대 → 코어 → 마무리 순서로 안내합니다. 타이머, 휴식, 일시정지·재개, 단계 건너뛰기, 횟수 조절과 수행 피드백을 지원합니다. |
| 동작 배우기 | 시연 자료, 시작 자세·동작 수행·자세 확인 설명, 원본 자료와 일부 외부 교육 링크를 제공합니다. |
| 운동 기록 | 월별 달력, 완료 횟수·운동한 날짜 수·총 운동 시간을 표시합니다. 날짜를 누르면 해당 날짜의 완료 루틴을 확인할 수 있습니다. |
| 체중 | 측정 날짜별 체중 입력·수정, 월별 추이 그래프, 직전 측정 및 최초 기록 대비 변화율을 제공합니다. |
| 설정 | 운동별 세트 가감·휴식 시간·효과음·한국어 음성 안내, 프로필 수정, JSON 백업·복원, 두 종류의 초기화를 제공합니다. |

### 처음 사용하기

1. 프로필을 입력하고 `확인`을 누릅니다.
2. 홈에서 추천 루틴과 `동작 배우기`를 확인합니다.
3. `운동 시작하기`를 누르고 단계별 안내에 따라 진행합니다.
4. 본운동에서 `했어요`, `너무 쉬웠어요`, `너무 어려웠어요`로 강도를 평가합니다.
5. 운동 완료 후 `운동 기록`에서 이력을 확인하고, `체중`에서 측정값을 기록합니다.

프로필 수정은 확인 버튼을 눌렀을 때 저장되며 새로 시작하는 세션에 반영됩니다. 진행 중인 세션의 종목 구성은 저장된 단계 목록을 사용합니다. 운동·휴식 중 `동작 배우기`를 열면 타이머가 일시정지되며, 창을 닫은 뒤 직접 재개해야 합니다.

### 월별 운동 기록

- 이전 달·다음 달 버튼, 월 선택 입력, `이번 달` 버튼으로 조회 월을 바꿉니다.
- 달력에서 같은 날 여러 번 완료한 운동도 횟수에 포함합니다.
- 월별로 완료 세션 수, 운동한 날짜 수, 총 운동 시간을 집계합니다.
- 날짜를 누르면 그날의 루틴 목록을 표시하고, `전체 보기`로 해당 월 전체 목록으로 돌아갑니다.
- 완료 시 저장된 세션을 기준으로 하며 진행 중인 세션은 완료 전까지 집계하지 않습니다. 단계 정보가 있는 기록은 수행 단계 수도 표시합니다.

### 날짜별 체중과 변화율

- 오늘 또는 과거의 유효한 날짜에 `30~250kg` 범위의 체중을 입력할 수 있습니다. 저장값은 소수점 한 자리로 반올림합니다.
- 같은 날짜에 다시 저장하면 해당 날짜의 기록을 수정합니다.
- 과거 날짜를 수정해도 현재 프로필 체중은 **날짜상 가장 최근 측정값**을 유지합니다.
- 월별 그래프는 실제 측정 날짜 간격을 반영합니다. 추이 선은 서로 다른 날짜의 기록이 두 개 이상일 때 표시합니다.
- 변화율은 다음과 같이 계산합니다.

```text
직전 측정 대비 (%) = (현재 측정값 − 직전 측정값) ÷ 직전 측정값 × 100
최초 기록 대비 (%) = (현재 측정값 − 최초 측정값) ÷ 최초 측정값 × 100
```

직전 측정일은 전날로 한정하지 않으며, 지난달 기록도 비교 기준이 될 수 있습니다. 첫 기록의 직전 대비 값은 `—`로 표시합니다. `+`는 증가, `−`는 감소입니다. 최초 대비 기준은 체중 기록의 가장 이른 측정값이며, 홈의 목표 진행률 계산에 쓰이는 프로필 초기 체중과 구분됩니다.

### 두 가지 초기화

설정의 `내 데이터`에 두 기능을 별도 버튼으로 제공합니다. **버튼을 눌러 확인창을 여는 것만으로는 삭제되지 않으며, 해당 확인창에서 확인을 눌러야 실행됩니다. 취소하면 기존 정보를 유지합니다.**

| 기능 | 유지하는 정보 | 초기화 범위 | 실행 후 |
|---|---|---|---|
| 기록·설정 초기화 | 프로필·신체정보·목표 체중 | 운동·체중 기록, 운동 설정, 난이도 진행도, 진행 중인 세션 | 홈으로 이동하고 프로필 체중을 오늘의 시작 체중 기록으로 남깁니다. |
| 프로필 포함 전체 초기화 | 개인 저장 정보 없음 | 프로필을 포함한 현재 데이터 및 이전 버전의 칼리코치 저장 정보 | 최초 프로필 입력 화면으로 이동합니다. |

전체 초기화 후에는 과거 버전 프로필이 자동 이전으로 다시 나타나지 않도록 처리합니다. 다운로드한 외부 JSON 백업 파일과 앱 소스·시연 파일은 이 초기화의 삭제 대상이 아닙니다.

## 3. 운동 구성과 추천 방식

### 동작 목록: 총 29개

본운동·보강용 23개와 준비·마무리 6개입니다. 사이드 플랭크 좌우는 각각 하나의 동작으로 계산합니다. 등록된 모든 동작을 매 세션에 수행하는 것은 아닙니다.

| 분류 | 동작 |
|---|---|
| 푸시 · 6개 | 벽 푸시업, 높은 지지대 푸시업, 무릎 푸시업, 일반 푸시업, 템포 푸시업, 좁은 푸시업 |
| 하체 · 5개 | 의자 스쿼트, 맨몸 스쿼트, 천천히 스쿼트, 스플릿 스쿼트, 리버스 런지 |
| 엉덩이 · 4개 | 글루트 브리지, 한발 글루트 브리지, 클램셸, 옆으로 누워 다리 들기 |
| 어깨·등 상부 보조 · 3개 | W 레이즈, T 레이즈, 리버스 스노우 엔젤 |
| 코어 · 5개 | 데드버그, 버드독, 플랭크, 왼쪽 사이드 플랭크, 오른쪽 사이드 플랭크 |
| 준비 · 4개 | 어깨·팔 가볍게 풀기, 고관절 워밍업, 앉아서 무릎 펴기, 복부 긴장·호흡 |
| 마무리 · 2개 | 종아리·발바닥 가볍게 풀기, 호흡하며 마무리 |

### 추천 엔진

추천 로직은 [coach-engine.js](coach-engine.js)에 있으며, 외부 AI API를 호출하지 않는 브라우저 내 규칙 기반 엔진입니다.

- A/B/C는 하체·상체 밀기·고관절 폄·견갑 보조·코어로 구성합니다. 주 2일은 A/B, 주 3일 이상은 A/B/C 순환이며 주 4~5일의 나머지는 걷기·회복일로 안내합니다.
- 설정에서 **초급·중급·고급**을 한 번 눌러 선택합니다. 선택한 수준에 따라 동작·반복·세트가 달라지며, 완료 횟수나 과거 푸시업 최대 기록이 선택 수준을 자동으로 올리지 않습니다.
- 초급은 벽 푸시업·양발 브리지, 중급은 무릎 푸시업·기본 전신운동, 고급은 일반 푸시업·한발 브리지·템포 스쿼트 등을 기본으로 사용합니다. 불편 부위와 확인한 지지대·수행 조건은 계속 반영합니다.
- 20/30/45분과 선택 수준을 함께 반영해 운동별 세트를 배분합니다. 시간 추정에 따라 세트를 줄이되 가능한 범주는 최소 1세트 유지합니다.
- 스쿼트·푸시업을 교대하고, 브리지·견갑 보조를 교대한 다음 코어를 수행합니다. 같은 종목의 연속 세트는 별도 긴 휴식을 사용합니다. 기본 휴식은 60초, 같은 종목 연속은 90초이며 목표가 감량이라고 휴식을 자동 축소하지 않습니다.
- 실제 반복·좌우 횟수와 남은 반복 여유를 세트마다 기록합니다. ‘수행 한계’에는 같은 세션의 남은 동작부터 반복·변형을 낮추고 다음 추천에도 반영합니다.
- 반복 목표는 선택 수준 안에서 조절하고, 쉬워졌다고 상위 수준이나 더 어려운 변형으로 자동 승급하지 않습니다. 수준은 사용자가 직접 변경하며 같은 수준을 다시 누르면 해당 기본 강도를 재적용합니다.
- 평소에는 운동 후 ‘완료’만 눌러 진행합니다. 실제 횟수 수정·환경·불편 부위·세트·휴식 세부 설정은 필요한 경우에만 펼칩니다.
- 통증은 별도 기록해 해당 범주의 남은 세트를 제외하고 일시정지합니다. 이후 추천에서도 제외하며 사용자가 증상 해소 후 재평가를 선택해야 해제됩니다.
- 의자·높은 지지대·스플릿 스쿼트 균형·사이드 플랭크 수행 가능 여부를 프로필에서 확인합니다. 불편 부위의 대체 후 최종 중복을 검사하고, 수행할 수 없는 범주를 다른 운동으로 중복해서 채우지 않습니다.
- 브리지와 고관절 벌림을 다른 운동 목적으로 분류합니다. W/T 레이즈는 견갑 보조로 표시합니다. 실제 당기기 부하가 부족하다는 안내를 유지하며 밴드 로우는 검수된 시연 자료 확보 후 추가할 확장 항목입니다.
- 같은 부위의 강한 운동 사이에 하루가 확보됐다면 바로 시작하고, 간격이 부족한 경우에 회복 선택을 안내합니다. 회복일에는 각 1세트의 가벼운 세션이나 걷기를 선택하며, 가벼운 세션은 근력 순서·주간 목표 횟수를 올리지 않습니다.
- 걷기는 날짜·시간·강도를 별도로 저장합니다. 주간 중강도 걷기 분량만 150분 목표에 합산하고, 근력 세션·휴식 시간은 합산하지 않습니다.

현재 간편 설정 규칙은 [간편 수준 설정과 날짜 입력 보완](docs/18_simple_levels_and_date_layout.md)에 정리했습니다. 이전 연구 기반 설계는 [운동 프로그램 재설계안](docs/17_training_program_redesign.md)에 남겨두었습니다. 임의의 불편 부위 체크만으로 대체 동작의 안전성이 보장되는 것은 아닙니다. 장기적인 운동 효과는 실제 부하·수행·회복·지속성에 따라 달라집니다.

## 4. 시연 자료와 미디어 관리

현재 **29개 동작 모두 MP4 재생 자료가 연결**되어 있습니다.

| 현재 적용 출처 | 수량 | 설명 |
|---|---:|---|
| 사용자 제공 GIF 변환 | 18개 | `media/gif/` 원본을 보존하고 MP4·정지 썸네일을 생성했습니다. 맨몸 스쿼트·푸시업도 사용자 자료로 교체했습니다. |
| Pexels | 10개 | 기존에 확보한 운동 시연 자료입니다. |
| Mixkit | 1개 | 마무리 호흡 자료입니다. |

- `tools/video_sources.json`이 운동 ID, 출처, 원본 경로, 파일명과 표시 문구를 관리합니다.
- `video-catalog.js`는 실제 앱이 읽는 재생 목록입니다.
- `media/videos/<운동ID>.mp4`와 같은 ID의 `.jpg` 썸네일을 사용합니다.
- 음소거·자동 반복·인라인 재생을 사용하며, 동작 배우기에서는 0.5배/1배와 눌러서 재생·일시정지를 지원합니다.
- 사용자 자료는 실제 사람, 인체 모형, 호흡 원리 그림이 섞여 있어 표시를 구분합니다. 29개 모두 실제 사람 촬영 영상이라는 뜻은 아닙니다.
- 사용자 자료의 MP4 재생에 실패하면 연결된 원본 GIF를, 그 외 자료는 기존 개념 GIF를 대체 표시합니다.
- 템포 푸시업·천천히 스쿼트는 제공 원본의 동작 주기를 편집해 **3초 하강·1초 상승**으로 맞췄습니다.
- 사용자 확인에 따라 `앉아서 무릎 번갈아 들기.gif`는 실제 내용에 맞게 **앉아서 무릎 펴기**로 이름과 설명을 변경했습니다.

출처가 기록되어 있다는 사실과 동작의 전문 검수·공개 재배포 권한 확인은 별개입니다. 사용자 제공 자료의 저작자·라이선스는 추정하지 않았습니다. 파일별 연결과 확인 범위는 [사용자 자료 매칭 기록](docs/15_user_media_mapping.md)에 정리했습니다.

### 관리 명령

일반 앱 실행에는 Python이나 FFmpeg가 필요하지 않습니다. 아래는 미디어를 다시 생성하거나 관리할 때 사용하는 개발 명령입니다.

```powershell
# Python 3.10+와 Pillow, PATH에 등록된 FFmpeg 필요
python tools/import_user_media.py

# 특정 사용자 자료만 다시 변환
python tools/import_user_media.py push squat

# 현재 MP4 파일과 출처 목록으로 앱 재생 목록 재생성
python tools/manage_media.py refresh

# 등록 출처 보기
python tools/manage_media.py list

# Mixkit 마무리 호흡 원본 받기: API 키 불필요
python tools/manage_media.py fetch cool2
```

Pexels API 수집에는 환경변수 `PEXELS_API_KEY`가 필요합니다. 키는 프런트엔드 코드·JSON·커밋에 넣지 않습니다. `fetch all`은 외부 제공 자료만 대상으로 하며 `media/pending/`에 저장합니다. 다운로드만으로 앱 재생 목록에 승격하지 않습니다. 사용자 원본은 `import_user_media.py`로 변환합니다.

## 5. 시스템 구조

프레임워크나 번들러 없이 동작하는 정적 HTML/CSS/JavaScript 애플리케이션입니다. 서버 측 애플리케이션과 데이터베이스는 없습니다.

```text
calicoach/
├─ index.html                  진입점, 스크립트 로딩 순서
├─ app.js                      화면 렌더링, 이벤트, 세션·기록·저장 관리
├─ coach-engine.js             운동 선택, 난이도·횟수 조절, 피드백 규칙
├─ exercise-guides.js          29개 동작의 단계별 설명과 교육 자료 링크
├─ styles.css                  모바일 화면, 달력·체중 표·운동 플레이어 스타일
├─ video-catalog.js            앱에서 읽는 재생 파일·원본 자료 목록
├─ source-candidates.js        초기 Pexels 후보 링크 목록
├─ sw.js                       앱 셸 캐시와 업데이트 처리
├─ manifest.webmanifest        PWA 이름·아이콘·시작 경로·표시 방식
├─ icons/                      앱 아이콘
├─ media/
│  ├─ *.gif                   기존 개념 시연·대체 표시 자료
│  ├─ gif/                    사용자 제공 원본 GIF 18개
│  ├─ videos/                 현재 재생용 MP4 29개와 JPG 썸네일
│  └─ pending/                수집 원본·검토 이미지·작업 보고서, Git 제외
├─ tools/
│  ├─ video_sources.json      전체 운동과 미디어 출처 매핑
│  ├─ import_user_media.py    사용자 GIF 변환·매핑·검사
│  ├─ manage_media.py         외부 수집·수동 승인·카탈로그 재생성

├─ tests/
```

`index.html`은 엔진, 가이드, 미디어 목록을 먼저 로드한 뒤 `app.js`를 실행합니다. `app.js`는 화면 상태와 사용자 데이터를 메모리에서 관리하고 변경 시 브라우저에 저장합니다. 추천 엔진은 UI와 분리되어 Node.js에서도 검사할 수 있습니다.

```text
프로필·수행 피드백 → coach-engine.js → 다음 루틴·목표 횟수
                              ↓
가이드·미디어 목록 → app.js → 홈·운동·월별 기록·체중·설정
                              ↕
                         localStorage
                              ↕
                         JSON 백업·복원
```

## 6. 저장 구조와 개인정보

주 저장 키는 `localStorage['calicoach.pwa.v3.device']`입니다. 키의 `v3`와 앱 표기 버전 `v1.4.1`, JSON 백업 형식 버전 `5`는 서로 다른 개념입니다.

| 필드 | 저장 내용 |
|---|---|
| `profile` | 이름·신체정보·초기/현재/목표 체중·운동 조건·불편 부위 |
| `settings` | 운동별 세트 가감·휴식·효과음·음성 설정 |
| `workouts` | 완료 날짜·루틴·운동 시간·원래 처방과 실제 세트 수행·좌우·여유 기록 |
| `weights` | 날짜와 측정 체중 |
| `programIndex`, `nextPlan` | 완료 세션에 따른 다음 루틴 순서 |
| `progress` | 운동별 목표·연속 성공·하향 정보와 범주별 변형 선택·통증 제외 |
| `legacyProgress` | 이전 규칙의 진행도 보관. 새 규칙의 승급 근거로 사용하지 않음 |
| `activities` | 날짜·분량·강도로 분리한 걷기 기록 |
| `trainingVersion` | 운동 추천·기록 규칙 형식 버전 2 |
| `active` | 진행 중인 세션의 단계 목록·타이머·수행 피드백 |

- 한 브라우저 저장 공간에 한 프로필을 사용합니다. 다른 기기나 브라우저로 자동 동기화하지 않습니다.
- 이름·신체정보·운동·체중 기록을 별도 백엔드 API로 전송하지 않습니다. 브라우저 저장 정보 자체를 암호화하는 기능은 없습니다.
- 앱 삭제·사이트 데이터 삭제·브라우저 저장 공간 정리로 기록이 사라질 수 있습니다. Safari와 홈 화면 PWA의 저장 공간이 다를 수 있습니다.
- 설정에서 JSON 백업과 복원을 제공합니다. 백업에는 개인 정보가 포함되며 복원은 현재 데이터를 교체합니다.
- 백업은 형식 버전 5로 내보내고 1~5를 읽습니다. 세트 처방·실제 수행·좌우 기록·걷기 기록을 보존하며, 과거 진행도는 보관하되 새 승급 근거로 쓰지 않습니다. 기존 다중 사용자 버전의 로컬 키를 읽는 이전 로직도 남아 있습니다.
- 전체 초기화는 현재 정보와 구버전 저장 키를 정리하고 개인 정보가 없는 초기 상태를 남겨 구버전 자동 복원을 막습니다.

## 7. 실행·설치·배포

### 로컬 실행

전체 소스와 `media/`, `icons/`를 같은 프로젝트 폴더에 두고 정적 웹 서버로 실행합니다. 별도 빌드나 npm 의존성 설치는 필요하지 않습니다.

Python이 설치된 환경의 예:

```powershell
cd C:\work\calicoach
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 엽니다. `file://`로 HTML을 여는 방식은 서비스 워커를 등록하지 않으므로 정적 서버 사용을 기준으로 확인합니다.

### PWA와 오프라인 범위

HTTPS 정적 호스팅 또는 localhost에서 서비스 워커를 사용합니다. 지원 브라우저의 설치·홈 화면 추가 기능으로 앱처럼 실행할 수 있습니다.

`sw.js`는 앱 셸과 기존 개념 GIF를 사전 캐시하고, 새 캐시 버전 활성화 시 이전 칼리코치 캐시를 정리합니다. 일반 요청은 네트워크를 우선 사용하고 실패하면 캐시를 확인합니다.

**MP4 요청은 바이트 범위 재생을 위해 서비스 워커가 가로채지 않습니다.** 사용자 원본 GIF 전체도 사전 캐시하지 않습니다. 따라서 현재 연결된 29개 재생 자료의 완전한 오프라인 사용을 보장하지 않으며, 미디어를 불러오려면 서버 접근이 필요할 수 있습니다.

### 정적 호스팅 업데이트

GitHub Pages 등 정적 호스팅에서 서비스할 수 있습니다. 배포할 때는 HTML·JS·CSS뿐 아니라 `media/videos/`와 사용 중인 원본 `media/gif/`, 기존 `media/*.gif`, 아이콘을 함께 반영해야 합니다. `.gitignore`의 `media/pending/`는 작업용 원본과 보고서를 배포에서 제외합니다.

코드나 시연 자료를 바꿀 때는 서비스 워커 캐시 버전을 갱신하고, 브라우저의 새로고침 후 실제 재생을 확인합니다. 이 문서의 수정은 커밋·푸시·온라인 배포를 자동 실행하지 않습니다.
